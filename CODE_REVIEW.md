# Оцінка коду парсингу резюме

Нижче — короткий, практичний review з пріоритетами.

## Що вже добре

- Логіка розбита на невеликі функції (`findCity`, `findAge`, `findPhone`, `findRealName`, ...).
- Є запасні сценарії (структурований формат → вільний текст).
- Є захист від падінь через `try/catch` в критичних місцях обробки Gmail/вкладень.
- Є дедуплікація по телефону через `Set`.

## Критичні проблеми (виправити першими)

1. **Конфіденційні дані в коді**
   - `CONFIG.FOLDER_ID` і особливо `CONFIG.NOTIFICATION_EMAIL` захардкоджені.
   - Ризик: витік даних, складність переносу між акаунтами.
   - Рішення: зберігати в `PropertiesService.getScriptProperties()`.

2. **Невірні/нестабільні регулярні вирази для імені**
   - У `isNameWord` використано `i` у перевірці великої літери: `^[А-ЯЄІЇҐ]` з `i` робить перевірку неточною.
   - Це може пропускати слова з малої літери.
   - Рішення: прибрати `i` для перевірки початкової великої букви.

3. **Помилка в списку міст та опечатки**
   - Є помилки: `Днипро` (має бути `Дніпро`), `Доніцьк` (`Донецьк`), `Сивирськодонецьк` (`Сєвєродонецьк`), `Чернигів` (`Чернігів`).
   - Рішення: виправити словник + додати нормалізацію `ї/і/є/ґ` та апострофів.

4. **Дублікати не контролюються при вкладеннях**
   - Перевірка `existingPhones` робиться лише на `messageData.phone` до обробки файлу.
   - Якщо з вкладення витягнувся новий телефон, він може продублюватися.
   - Рішення: перевіряти дубль перед `appendRow` за фінальним `finalPhone` і оновлювати `existingPhones.add(finalPhone)` після запису.

5. **`Drive.Files.insert` залежить від Advanced Service**
   - Код впаде, якщо `Drive API` не увімкнений у Apps Script.
   - Рішення: або документувати обов'язкове ввімкнення, або додати fail-fast перевірку на старті.

## Важливі покращення

1. **Телефон: нормалізація формату**
   - Зараз повертається «як знайдено». Через це `+380...` і `380...` можуть вважатися різними.
   - Рішення: функція `normalizePhone(phone)`:
     - видаляти пробіли/дужки/дефіси;
     - приводити до `+380XXXXXXXXX` для UA номерів;
     - саме normalized-значення зберігати в таблицю і Set.

2. **Пошук віку може зловити не ту дату**
   - Regex дати бере першу будь-яку дату в тексті (може бути дата досвіду, сертифікату тощо).
   - Рішення: шукати спершу мітки `дата народження|д.н.|birth` поруч з датою.

3. **`findPhone` у structured-режимі обрізає номер**
   - `(?:телефон|phone)...(\+?\d+)` бере тільки суцільну цифро-послідовність до пробілу.
   - Рішення: дозволити формат із пробілами/дужками/дефісами, як у `PHONE_REGEX`.

4. **Скан перших 50 рядків у `findRealName`**
   - Іноді ім’я нижче (після заголовків/шапки).
   - Рішення: або збільшити ліміт (напр. 120), або пріоритезувати перші N символів/блоків за ключовими секціями.

5. **Silent catch у нотифікаціях**
   - `catch {}` у `sendEmailNotification`/`sendErrorNotification` ховає проблеми.
   - Рішення: хоча б `Logger.log` в catch.

## Якість даних та локалізація

- У коді змішані українські/російські ключі (`місто|город`, `ім'я|имя`, `ОТКЛИК`).
- Краще винести словники ключових слів у `CONFIG`.
- Статуси (`"Не знайдено"`, `"—"`) теж краще в константи (уникнення typo).

## Продуктивність та ліміти Apps Script

- `appendRow` у циклах повільний при великих обсягах.
- Рішення: буферизувати рядки і писати `setValues()` пачками.
- `Utilities.sleep(1500/2000)` при великій кількості вкладень швидко з’їдає runtime.
  - Можна скорочувати через ретраї з backoff лише при помилці відкриття документа.

## Мінімальний рефакторинг (план)

1. Винести в `CONFIG`: ключові слова, плейсхолдери, service-слова, статуси.
2. Додати `normalizePhone()` і використовувати всюди (пошук, запис, дедуп).
3. Виправити regex-и в `isNameWord` та `findPhone`.
4. Виправити словник міст + опечатки.
5. Додати dedup check після парсингу вкладення.
6. Замінити частину `appendRow` на пакетний запис.

## Дрібні баги/неохайності

- Коментар: `Т��п файла` (кодування/опечатка).
- `extractFromWord`: перевірка extension дублює `docx?|doc`.
- У `findCity` межі слова `\b` для кирилиці можуть працювати нестабільно в деяких випадках; краще робити пошук через нормалізований текст і `includes` по токенах/словнику.
